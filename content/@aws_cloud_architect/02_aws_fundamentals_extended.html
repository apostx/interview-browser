Infrastructure as Code (IaC)Infrastructure as Code (IaC)

Defining infrastructure in code instead of clicking in the console — so it's versioned, repeatable, and reviewable. Non-negotiable for this role.Infrastruktúra kódban definiálása a console-ban kattintgatás helyett — így verziózott, ismételhető, és review-zható. Nem alku tárgya ennél a szerepnél.

PointLényegManual console changes cause "drift" (code no longer matches reality). The discipline is that all changes go through code, so environments are reproducible and auditable.A kézi console-változtatások „driftet" okoznak (a kód már nem egyezik a valósággal). A fegyelem az, hogy minden változás kódon át megy, így a környezetek reprodukálhatók és auditálhatók.

02

Terraform vs CloudFormation vs CDKTerraform vs CloudFormation vs CDK

The main IaC tools. CloudFormation is AWS-native (AWS manages the state); Terraform is cloud-agnostic and the market standard; CDK lets you write infrastructure in a real programming language.A fő IaC eszközök. A CloudFormation AWS-natív (az AWS kezeli a state-et); a Terraform felhő-agnosztikus és a piaci standard; a CDK lehetővé teszi az infrastruktúra írását valódi programnyelven.

PointLényegThe choice is org and lifecycle fit, not just portability: existing tooling, team skills, multi-cloud needs. Pulumi and CDK both let you use general-purpose languages; CloudFormation and Terraform use declarative templates.A választás org- és életciklus-illeszkedés, nem csak hordozhatóság: meglévő eszközök, csapat-készségek, multi-cloud igények. A Pulumi és a CDK is általános célú nyelveket enged; a CloudFormation és a Terraform deklaratív sablonokat használ.

03

Terraform StateTerraform state

Terraform's record of what it manages. It must be stored remotely and locked, or concurrent runs corrupt it.A Terraform feljegyzése arról, mit kezel. Távolról kell tárolni és lockolni, különben a párhuzamos futások megrongálják.

PointLényegStore it in an encrypted, versioned S3 bucket with native locking (use_lockfile — the old DynamoDB lock table is deprecated). Separate state per environment and client. State holds secrets in plaintext, so lock down access.Tárold titkosított, verziózott S3 bucketben natív lockinggal (use_lockfile — a régi DynamoDB lock-tábla deprecated). Külön state környezetenként és ügyfelenként. A state titkokat tart sima szövegben, tehát zárd le a hozzáférést.

04

Drift & Moved BlocksDrift & moved blokkok

Drift = the real infrastructure diverged from the code (usually a manual change). A moved block tells Terraform a resource was renamed, not destroyed.Drift = a valódi infrastruktúra eltért a kódtól (általában egy kézi változtatás). Egy moved blokk megmondja a Terraformnak, hogy egy erőforrás átnevezésre került, nem törlésre.

PointLényegAlways read the plan before applying — a destructive plan from drift can wreck things. A plan step in CI surfaces drift early. Import a manual change into code if it should stay, or apply to revert it.Mindig olvasd a plant az apply előtt — egy driftből jövő destruktív plan tönkretehet dolgokat. Egy plan lépés a CI-ban korán felszínre hozza a driftet. Importáld a kézi változtatást a kódba, ha maradnia kell, vagy alkalmazz a visszaállításához.

05

CI/CD PipelinesCI/CD pipeline-ok

Automated build, test, and deploy without manual steps. This role names GitLab CI and GitHub Actions specifically.Automatizált build, teszt, és telepítés kézi lépések nélkül. Ez a szerep kifejezetten a GitLab CI-t és GitHub Actionst nevezi meg.

PointLényegThe pipeline is where quality and security are enforced mechanically: automated tests, security scanning, a Terraform plan step, an approval gate for prod. Shifting these checks "left" into the pipeline is a concrete reliability win.A pipeline az, ahol a minőség és biztonság mechanikusan kikényszerül: automatizált tesztek, biztonsági szkennelés, egy Terraform plan lépés, egy jóváhagyási kapu produkcióhoz. Ezek balra tolása a pipeline-ba konkrét megbízhatósági nyereség.

06

OIDC Federation for PipelinesOIDC föderáció pipeline-okhoz

Letting a pipeline authenticate to AWS with a short-lived token instead of stored access keys.Egy pipeline autentikálása az AWS felé rövid életű tokennel a tárolt access key-ek helyett.

PointLényegGitLab/GitHub present an OIDC token that AWS exchanges for temporary role credentials — no long-lived secret in the CI system to leak. This is current best practice; if your answer stores an access key in CI, expect "why not OIDC?"A GitLab/GitHub egy OIDC tokent mutat be, amit az AWS ideiglenes role-hitelesítő adatokra vált — nincs hosszú életű titok a CI-ban, ami kiszivároghatna. Ez a jelenlegi best practice; ha a válaszod access key-t tárol a CI-ban, számíts a „miért nem OIDC?"-re.

Deployment StrategiesTelepítési stratégiák

How you release without downtime: rolling, blue-green, and canary.Hogyan adsz ki leállás nélkül: rolling, blue-green, és canary.

PointLényegRolling = replace instances gradually. Blue-green = switch all traffic to a new environment at once, with instant rollback. Canary = send a small % first and watch metrics. Tie rollback to a health alarm so a bad deploy auto-reverts.Rolling = instance-ok fokozatos cseréje. Blue-green = az összes forgalom átkapcsolása egy új környezetre egyszerre, azonnali visszagörgetéssel. Canary = előbb egy kis % küldése és a metrikák figyelése. Kösd a rollbacket egy health-riasztáshoz, hogy egy rossz deploy automatikusan visszaálljon.

The Three Pillars of ObservabilityAz observability három pillére

Metrics, logs, and traces — being able to answer "what is it doing and why" from the outside.Metrikák, logok, és trace-ek — az a képesség, hogy kívülről megválaszold, „mit csinál és miért".

PointLényegMetrics tell you what (rates, latency), traces tell you where (which service ate the time), logs tell you why (the detail of an event). You need all three: a metric flags a latency spike, a trace localises it, the logs explain it.A metrikák megmondják, mi (ráták, késleltetés), a trace-ek megmondják, hol (melyik szolgáltatás ette az időt), a logok megmondják, miért (egy esemény részlete). Mindhárom kell: egy metrika jelzi a késleltetés-csúcsot, egy trace lokalizálja, a logok megmagyarázzák.

09

CloudWatchCloudWatch

AWS's native monitoring service — collects metrics, logs, and alarms from AWS services automatically.Az AWS natív monitoring-szolgáltatása — automatikusan gyűjt metrikákat, logokat, és riasztásokat az AWS-szolgáltatásokból.

PointLényegZero-setup for AWS services and the path of least resistance for an all-AWS shop. Watch the cost — custom and high-resolution metrics, and large log ingestion, all bill per unit; high-cardinality custom metrics add up fast.Nulla-beállítás az AWS-szolgáltatásokhoz és a legkisebb ellenállás útja egy teljesen AWS-boltnak. Figyeld a költséget — az egyedi és nagy felbontású metrikák, és a nagy log-bevitel mind egységenként számláznak; a magas kardinalitású egyedi metrikák gyorsan összeadódnak.

10

Prometheus, Grafana & the ELK/OpenSearch StackPrometheus, Grafana & az ELK/OpenSearch stack

The open-source observability stack: Prometheus (metrics), Grafana (dashboards), ELK/OpenSearch (logs). The standard for Kubernetes and multi-cloud.A nyílt forrású observability stack: Prometheus (metrikák), Grafana (dashboardok), ELK/OpenSearch (logok). A standard Kuberneteshez és multi-cloudhoz.

PointLényegRicher querying (PromQL) and dashboards than CloudWatch, and avoids its per-metric cost at high cardinality. Many teams run both: CloudWatch for AWS metrics, Prometheus/Grafana for app and cluster metrics.Gazdagabb lekérdezés (PromQL) és dashboardok, mint a CloudWatch, és elkerüli annak metrikánkénti költségét magas kardinalitásnál. Sok csapat mindkettőt futtatja: CloudWatch az AWS-metrikákhoz, Prometheus/Grafana az app- és klaszter-metrikákhoz.

11

X-Ray & Distributed TracingX-Ray & elosztott trace-elés

Following a single request as it hops across services to see where the time went. X-Ray is AWS's tracer; OpenTelemetry is the open standard.Egy kérés követése, ahogy szolgáltatásokon ugrál át, hogy lásd, hol ment el az idő. Az X-Ray az AWS trace-elője; az OpenTelemetry a nyílt standard.

PointLényegTraces are what turn "the system is slow" into "this specific downstream call is slow" in a distributed system. Essential once you have more than a couple of services calling each other.A trace-ek azok, amelyek a „a rendszer lassú"-t „ez a konkrét lejjebbi hívás lassú"-vá alakítják egy elosztott rendszerben. Elengedhetetlen, ha néhánynál több szolgáltatásod hívja egymást.

12

SLOs & AlertingSLO-k & riasztás

An SLO (Service Level Objective) is a target for reliability; alerting should fire on symptoms users feel, not on every metric.Egy SLO (Service Level Objective) egy megbízhatósági cél; a riasztás a felhasználók által érzett tünetekre szóljon, ne minden metrikára.

PointLényegAlert on error rate, latency (p95/p99, not average), and saturation — the signals that mean someone's being hurt now. Alerting on raw CPU or everything produces pager fatigue, after which real alerts get ignored.Riassz hibaarányra, késleltetésre (p95/p99, nem átlag), és telítettségre — a jelekre, amelyek azt jelentik, valakit most bánt. A nyers CPU-ra vagy mindenre riasztás pager-fáradtságot szül, ami után a valódi riasztásokat figyelmen kívül hagyják.

KMS & Encryption at RestKMS & titkosítás nyugalmi állapotban

KMS (Key Management Service) manages encryption keys. EBS and RDS encryption use KMS; S3 defaults to SSE-S3 with optional SSE-KMS.A KMS (Key Management Service) titkosítási kulcsokat kezel. Az EBS és RDS titkosítása KMS-t használ; az S3 alapból SSE-S3, opcionális SSE-KMS-sel.

PointLényegEnvelope encryption (data keys encrypted by a master key), key rotation, and customer-managed keys with tight policies when you need to control and audit who can decrypt. In transit is TLS everywhere. S3 can also use DSSE-KMS for stronger requirements.Envelope encryption (mesterkulccsal titkosított adatkulcsok), kulcsrotáció, és customer-managed kulcsok szoros policy-kkel, amikor kontrollálni és auditálni kell, ki dekódolhat. Átvitelben mindenhol TLS. Az S3 DSSE-KMS-t is használhat erősebb követelményekhez.

14

Secrets Manager & Parameter StoreSecrets Manager & Parameter Store

Where secrets (passwords, API keys) belong — never in code or committed env files.Ahová a titkok (jelszavak, API-kulcsok) tartoznak — soha nem kódban vagy commitolt env-fájlokban.

PointLényegSecrets Manager adds automatic rotation (e.g. rotate an RDS password in one step) — its edge over the cheaper Parameter Store. Apps fetch secrets at runtime via their IAM role, so the secret is never stored with the app.A Secrets Manager automatikus rotációt ad (pl. egy RDS-jelszó rotálása egy lépésben) — ez az előnye az olcsóbb Parameter Store-ral szemben. Az appok futásidőben kérik le a titkokat az IAM role-jukon át, így a titok sosem tárolódik az appal.

15

CloudTrail, Config & GuardDutyCloudTrail, Config & GuardDuty

The audit and threat-detection trio. CloudTrail logs API activity; Config tracks resource state; GuardDuty watches for threats.Az audit és fenyegetés-észlelő trió. A CloudTrail API-aktivitást logol; a Config követi az erőforrás-állapotot; a GuardDuty fenyegetéseket figyel.

PointLényegCloudTrail is the foundation of any audit — management events log by default, data events (S3 object-level, Lambda) need explicit enabling. Config flags non-compliant changes; GuardDuty spots anomalous behaviour. Never disable CloudTrail.A CloudTrail bármely audit alapja — a management eventek alapból logolódnak, a data eventek (S3 objektum-szint, Lambda) explicit engedélyezést igényelnek. A Config jelzi a nem-megfelelő változásokat; a GuardDuty észleli az anomális viselkedést. Sose tiltsd le a CloudTrailt.

16

Defence in Depth & ComplianceMélységi védelem & compliance

Security is layered — no single control is a strategy. Compliance (GDPR, HIPAA) needs an audit trail and provable controls.A biztonság rétegzett — egyetlen kontroll sem stratégia. A compliance (GDPR, HIPAA) audit-nyomot és bizonyítható kontrollokat igényel.

PointLényegDefence in depth = an attacker must get through IAM and network isolation and encryption. For EU compliance: resources pinned to an EU region (via SCP), encrypted, with CloudTrail and Config for the audit trail. Data residency is the recurring requirement.Mélységi védelem = egy támadónak át kell jutnia az IAM-en és a hálózati izoláción és a titkosításon. EU-compliancehez: EU-régióhoz szögezett erőforrások (SCP-vel), titkosítva, CloudTraillel és Config-gal az audit-nyomhoz. Az adat-honosság a visszatérő követelmény.

AWS Organizations & SCPsAWS Organizations & SCP-k

Organizations groups many AWS accounts under one umbrella; Service Control Policies (SCPs) set guardrails no account can exceed.Az Organizations sok AWS-accountot csoportosít egy ernyő alá; a Service Control Policy-k (SCP-k) védőkorlátokat állítanak, amiket egy account sem léphet át.

PointLényegAccounts are the strongest isolation boundary (a hard blast-radius limit). SCPs enforce "only EU regions" or "CloudTrail can't be disabled" fleet-wide. For a consultancy managing many clients, this is the foundation of governance.Az accountok a legerősebb izolációs határ (kemény blast-radius korlát). Az SCP-k kikényszerítik a „csak EU régiók" vagy „a CloudTrail nem tiltható le" szabályt flotta-szinten. Egy sok ügyfelet kezelő tanácsadónak ez a governance alapja.

18

Control Tower & Landing ZonesControl Tower & landing zone-ok

Control Tower sets up a multi-account "landing zone" with best practices baked in — the standard enterprise starting point.A Control Tower egy multi-account „landing zone-t" állít be beépített best practice-ekkel — a standard vállalati kiindulópont.

PointLényegA landing zone typically includes: Organizational Units, a logging account (aggregates CloudTrail), a security account (GuardDuty), a shared-services account, and centralised identity (IAM Identity Center) so people get scoped, temporary access via role assumption.Egy landing zone jellemzően tartalmaz: Organizational Unitokat, egy logging accountot (aggregálja a CloudTrailt), egy security accountot (GuardDuty), egy shared-services accountot, és központosított identitást (IAM Identity Center), így az emberek szűkített, ideiglenes hozzáférést kapnak role-felvétellel.

19

Cross-Account Role AssumptionCross-account role-felvétel

How people and pipelines get access across accounts: authenticate once centrally, then assume a scoped role in the target account.Ahogy az emberek és pipeline-ok hozzáférést kapnak accountok között: egyszer autentikálnak központilag, majd felvesznek egy szűkített role-t a cél-accountban.

PointLényegNobody has standing broad access — access is temporary, scoped, and assumed when needed, with an audit trail of who assumed what. This keeps the account isolation real; separate accounts only help if the access between them is tightly controlled.Senkinek nincs állandó tág hozzáférése — a hozzáférés ideiglenes, szűkített, és szükség esetén felvett, audit-nyommal arról, ki mit vett fel. Ez tartja valódinak az account-izolációt; a külön accountok csak akkor segítenek, ha a köztük lévő hozzáférés szorosan kontrollált.

The 7 Rs of MigrationA migráció 7 R-je

AWS's vocabulary for how to migrate each workload: rehost, relocate, replatform, refactor, repurchase, retain, retire.Az AWS szókészlete arról, hogyan migrálj minden workloadot: rehost, relocate, replatform, refactor, repurchase, retain, retire.

PointLényegRehost = lift-and-shift as-is. Relocate = move a virtualised environment with minimal change (e.g. VMware Cloud on AWS). Replatform = lift and tweak (self-managed DB → RDS). Refactor = re-architect for cloud-native. Plus repurchase (switch to SaaS), retain (leave as-is), retire (decommission). Pick per component.Rehost = lift-and-shift ahogy van. Relocate = egy virtualizált környezet mozgatása minimális változtatással (pl. VMware Cloud on AWS). Replatform = emelés és igazítás (self-managed DB → RDS). Refactor = újratervezés cloud-native-re. Plusz repurchase (váltás SaaS-ra), retain (hagyd ahogy van), retire (leszerelés). Komponensenként válaszd.

21

DMS & Application Migration ServiceDMS & Application Migration Service

The migration tooling. DMS (Database Migration Service) moves databases with minimal downtime; AWS Application Migration Service (MGN) lift-and-shifts whole servers.A migrációs eszközök. A DMS (Database Migration Service) adatbázisokat mozgat minimális leállással; az AWS Application Migration Service (MGN) egész szervereket lift-and-shiftel.

PointLényegDMS does an initial load then keeps the target in sync via change data capture, so the cutover window shrinks to the moment you switch traffic — not the hours a full copy would take. Continuous replication is what makes low-downtime migration possible.A DMS egy kezdeti betöltést csinál, majd szinkronban tartja a célt change data capture-rel, így az átállási ablak arra a pillanatra zsugorodik, amikor a forgalmat átkapcsolod — nem az órákra, amit egy teljes másolat venne. A folyamatos replikáció teszi lehetővé az alacsony-leállású migrációt.

22

The Strangler PatternA strangler minta

Migrate incrementally by routing slices of traffic to the new system while the old one still runs — the opposite of a risky big-bang cutover.Migrálj inkrementálisan úgy, hogy a forgalom szeleteit az új rendszerre irányítod, míg a régi még fut — egy kockázatos big-bang átállás ellentéte.

PointLényegYou replace the legacy system piece by piece; each slice is validated before the next, both systems run in parallel during the transition, and rollback stays cheap. This incremental, reversible framing is what a client wants to hear.A legacy rendszert darabonként cseréled; minden szeletet validálsz a következő előtt, mindkét rendszer párhuzamosan fut az átmenet alatt, és a visszagörgetés olcsó marad. Ez az inkrementális, visszafordítható keretezés az, amit egy ügyfél hallani akar.

SQS & Dead-Letter QueuesSQS & dead-letter queue-k

SQS (Simple Queue Service) is a managed message queue that decouples producers from consumers. A dead-letter queue (DLQ) catches messages that repeatedly fail.Az SQS (Simple Queue Service) egy menedzselt üzenetsor, amely szétcsatolja a termelőket a fogyasztóktól. Egy dead-letter queue (DLQ) elkapja az ismételten hibázó üzeneteket.

PointLényegA queue absorbs bursts and lets consumers process at their own pace. The DLQ means one poison message doesn't block the whole queue — it's moved aside for inspection. Consumers should be idempotent (at-least-once delivery means a message can arrive twice).Egy sor elnyeli a csúcsokat, és hagyja a fogyasztókat saját tempójukban feldolgozni. A DLQ azt jelenti, hogy egy méreg-üzenet nem blokkolja az egész sort — félreteszi vizsgálatra. A fogyasztóknak idempotensnek kell lenniük (az at-least-once kézbesítés azt jelenti, egy üzenet kétszer is megérkezhet).

24

Kinesis, MSK & KafkaKinesis, MSK & Kafka

Streaming platforms for high-volume ordered event data with replay. Kinesis is AWS-native; MSK is managed Apache Kafka.Streaming platformok nagy volumenű, rendezett esemény-adathoz visszajátszással. A Kinesis AWS-natív; az MSK menedzselt Apache Kafka.

PointLényegUse these (over SQS) when you need ordering, high throughput, and the ability to replay history — an event log rather than a work queue. Ordering is preserved within a partition; partition by the key that needs order (e.g. device id).Ezeket használd (az SQS helyett), amikor sorrend, nagy áteresztőképesség, és a történet visszajátszásának képessége kell — egy esemény-log, nem egy munkasor. A sorrend egy partíción belül megőrződik; partícionálj a sorrendet igénylő kulcs szerint (pl. eszköz-azonosító).

25

Athena & Data LakesAthena & data lake-ek

A data lake is raw data stored cheaply in S3; Athena queries it in place with SQL, no database to load.Egy data lake nyers adat, olcsón S3-ban tárolva; az Athena helyben lekérdezi SQL-lel, betöltendő adatbázis nélkül.

PointLényegStore huge volumes of events/logs in S3, then run SQL analytics with Athena — you pay per data scanned. Great for analytics on data you don't need in a live database. The output store for many event pipelines.Tárolj hatalmas mennyiségű eseményt/logot S3-ban, majd futtass SQL-analitikát Athenával — a beolvasott adat után fizetsz. Remek analitikához olyan adaton, ami nem kell egy élő adatbázisban. Sok esemény-pipeline kimeneti tárolója.

26

CognitoCognito

Managed user authentication and identity for your applications — sign-up, sign-in, and tokens without building your own auth.Menedzselt felhasználó-autentikáció és identitás az alkalmazásaidhoz — regisztráció, bejelentkezés, és tokenek saját auth építése nélkül.

PointLényegHandles user pools (your app's users), federated login (Google, an enterprise IdP), and issues tokens. In a multi-tenant design, the auth layer is where tenant identity enters the request so every data access can be scoped.Kezeli a user poolokat (az appod felhasználói), a föderált bejelentkezést (Google, egy vállalati IdP), és tokeneket bocsát ki. Egy multi-tenant tervben az auth-réteg az, ahol a tenant-identitás belép a kérésbe, hogy minden adathozzáférés szűkíthető legyen.

BedrockBedrock

Managed access to foundation models (LLMs) through one API — no GPU fleet to run, with AWS identity, encryption, and network controls.Menedzselt hozzáférés alapmodellekhez (LLM-ekhez) egy API-n át — nincs futtatandó GPU-flotta, AWS identitással, titkosítással, és hálózati kontrollokkal.

PointLényegModel providers don't get your account or prompts, and you can reach it privately via a VPC endpoint (PrivateLink). Self-hosting (SageMaker) is for full control or a specific fine-tuned model.A modell-szolgáltatók nem kapják meg az accountodat vagy promptjaidat, és privátan elérheted egy VPC endpointon (PrivateLink) át. RAG (Retrieval-Augmented Generation)RAG (Retrieval-Augmented Generation)

Grounding an LLM in your own data by retrieving relevant chunks and putting them in the prompt — so answers are current and citeable.Egy LLM megalapozása a saját adatodban úgy, hogy releváns darabokat kérsz le és a promptba teszed — így a válaszok aktuálisak és idézhetők.

PointLényegRAG vs fine-tuning is the key GenAI distinction: RAG injects facts at query time (update the documents, not the model; citeable; per-user access control). Fine-tuning changes the model's behaviour or style, not for feeding it facts. For a knowledge base, RAG is almost always the right first answer.A RAG vs fine-tuning a fő GenAI-megkülönböztetés: a RAG tényeket injektál lekérdezéskor (a dokumentumokat frissíted, nem a modellt; idézhető; felhasználónkénti hozzáférés-vezérlés). A fine-tuning a modell viselkedését vagy stílusát változtatja, nem tények betáplálására. Egy tudásbázishoz a RAG szinte mindig a helyes első válasz.

Vector Databases & EmbeddingsVektoradatbázisok & embeddingek

Embeddings are numerical representations of text; a vector database stores them and finds the ones most similar to a query. The retrieval engine behind RAG.Az embeddingek szöveg numerikus reprezentációi; egy vektoradatbázis tárolja őket, és megtalálja a kérdéshez leghasonlóbbakat. A RAG mögötti lekérési motor.

PointLényegOn AWS the options: OpenSearch with its vector engine, RDS/Aurora PostgreSQL with pgvector, or a dedicated store like Pinecone. It's a normal data-layer choice: pgvector if you already run Postgres and volume is modest, OpenSearch/dedicated when scale demands it.AWS-en az opciók: OpenSearch a vektor-motorjával, RDS/Aurora PostgreSQL a pgvector-rel, vagy egy dedikált tároló, mint a Pinecone. Ez egy normális adatréteg-döntés: pgvector, ha már futtatsz Postgrest és a volumen szerény, OpenSearch/dedikált, amikor a lépték megköveteli.

Savings Plans, Reserved & SpotSavings Plan, Reserved & Spot

The pricing models that cut compute cost below on-demand. Savings Plans/Reserved = commit for a discount; Spot = spare capacity, very cheap but reclaimable.Az árazási modellek, amelyek az on-demand alá vágják a számítási költséget. Savings Plan/Reserved = elköteleződés kedvezményért; Spot = tartalék kapacitás, nagyon olcsó de visszavehető.

PointLényegSavings Plans/Reserved: up to ~70% off for a 1–3 year commitment (steady baseline load). Spot: up to ~90% off but AWS can reclaim it with 2 minutes' notice — only for fault-tolerant, interruptible work. A strong pattern: baseline on Reserved, burst on Spot.Savings Plan/Reserved: akár ~70% kedvezmény 1–3 éves elköteleződésért (állandó alapterhelés). Spot: akár ~90% kedvezmény, de az AWS 2 perc értesítéssel visszaveheti — csak hibatűrő, megszakítható munkához. Erős minta: alapvonal Reserveden, csúcs Spoton.

Right-Sizing & Cost VisibilityRight-sizing & költség-láthatóság

Matching resources to actual need, and making spend visible with Cost Explorer, tagging, and budgets.Az erőforrások tényleges igényhez illesztése, és a költés láthatóvá tétele Cost Explorerrel, címkézéssel, és budgetekkel.

PointLényegConsistent tags let Cost Explorer attribute spend per team/client/environment (essential for a consultancy). Budgets with alerts catch a spike early instead of at month-end. The big architectural savings hide in data transfer (NAT, cross-AZ) and over-provisioning — cost optimisation is continuous, not a one-off.A következetes címkék lehetővé teszik a Cost Explorernek a költés csapatonként/ügyfelenként/környezetenként rendelését (elengedhetetlen egy tanácsadónak). A riasztásos budgetek korán elkapnak egy csúcsot, nem hónap végén. A nagy architekturális megtakarítások az adatátvitelben (NAT, cross-AZ) és a túlméretezésben rejtőznek — a költségoptimalizáció folyamatos, nem egyszeri.

The Well-Architected FrameworkA Well-Architected keretrendszer

AWS's six-pillar lens for evaluating any architecture: Operational Excellence, Security, Reliability, Performance Efficiency, Cost Optimization, Sustainability.Az AWS hatpilléres nézőpontja bármely architektúra értékeléséhez: Működési kiválóság, Biztonság, Megbízhatóság, Teljesítmény-hatékonyság, Költségoptimalizáció, Fenntarthatóság.

PointLényegUse it as a checklist that stops you tunnel-visioning on one dimension — when you propose a design, walk the pillars ("reliable via Multi-AZ, secured with least-privilege IAM, cost-optimised by scaling to zero"). Don't recite it as a list; apply it as a lens to the specific design.Használd ellenőrzőlistaként, ami megakadályozza, hogy egy dimenzióra szűkülj — amikor tervet javasolsz, vedd végig a pilléreket („Multi-AZ-vel megbízható, legkisebb jogosultságú IAM-mel biztosított, nullára skálázással költséghatékony"). Ne mondd fel listaként; alkalmazd nézőpontként a konkrét tervre.
